How this app is wired

A simple story of how a button tap becomes a server call and back. Six layers, one direction, no surprises. Once you see the shape, every file makes sense.

🧠

The mental model in one line

The View shows. The ViewModel thinks. The Service talks to the server. The APIClient is the only thing that touches the wire. That's the whole app — the rest is just folders.

Decides which screen to show. Nothing else.

What lives here

The single @main App struct. Reads the auth state and shows either the login screen or the main tabs.

What it does NOT do

  • No network calls
  • No styling

🔐

Auth & storage

The credential boundary. Nothing else holds the token.

Core/Authentication/
What lives here

AuthSession (an @Observable holder), KeychainManager (writes to Apple Keychain), and the URLSession cookie store (holds the refresh token).

The rule
  • Only AuthSession reads/writes the access token
  • The refresh token never enters Swift code (it's an HttpOnly cookie)
  • All other layers ask AuthSession, they never touch Keychain directly
03

The four SwiftUI patterns in play

When you read any file, one of these four shapes is happening.

@Observable

The state holder

One class per feature, holds everything the view needs. SwiftUI re-renders automatically when any property changes.

// TodayViewModel.swift @Observable final class TodayViewModel { var tasks: [TaskItem] = [] var isLoading = false func loadData() async { isLoading = true defer { isLoading = false } self.tasks = try await service.listActive() } }
@State + @Environment

The view's memory

The view owns a @State ViewModel. The view reads it. That's it. The view has no other state.

// TodayView.swift struct TodayView: View { @State private var vm = TodayViewModel() var body: some View { List(vm.tasks) { task in Text(task.title) } .task { await vm.loadData() } } }
Sendable struct

The dumb talker

A service is a struct with one method per endpoint. No state, no logic. The protocol makes it injectable for tests.

// TaskService.swift struct TaskService: Sendable { let api: any APIRequesting func listActive() async throws -> [TaskItem] { try await api.request(.listTasks) } }
enum + protocol

The type-safe path

Every endpoint is a case in an enum. Paths are not strings scattered around — they're cases the compiler can check.

// Endpoint.swift enum AppEndpoint: Endpoint { case listTasks case completeTask(id: String) case startFocus(taskId: String) var path: String { switch self { case .listTasks: "/api/v1/tasks" case .completeTask(let id): "/api/v1/tasks/\(id)" case .startFocus(let id): "/api/v1/focus" } } }
04

The three things to never do

✕

No networking in a View

If a view calls URLSession, fetch, or any HTTP thing directly — it belongs in a service. Views call viewModel.loadData() only.

✕

No calling a View from a Service

The arrow only goes one way: View → ViewModel → Service → APIClient. Services return models, not UI state. ViewModels own UI state.

✕

No storing the token anywhere else

Only AuthSession reads and writes the access token. If you find yourself reaching for UserDefaults or a global variable for auth — stop.
